# Corpus Schema

The corpus is generated by `scripts/generate_corpus.py` into:

- `data/corpus/<tenant>/<doc_id>.md` — one Markdown file per document version.
- `data/manifests/corpus.json` — the canonical manifest consumed by ingestion and evals.

## Manifest

```json
{
  "generated_at": "2026-11-03T00:00:00Z",
  "product": "Helios",
  "tenants": ["northwind", "acme"],
  "versions": ["v1", "v2", "v3"],
  "documents": [
    {
      "doc_id": "helios-api-keys",
      "tenant_id": "northwind",
      "title": "API keys",
      "doc_type": "api",
      "version": "v3",
      "effective_from": "2026-01-15",
      "superseded_at": null,
      "url_path": "/api/keys",
      "blocks": [
        {
          "block_id": "b1",
          "page": 1,
          "heading": "Overview",
          "anchor": "#overview",
          "text": "API keys authenticate requests to the Helios API."
        }
      ]
    }
  ],
  "failure_fixtures": {
    "stale_version": ["helios-api-keys@v1"],
    "wrong_page_citation": ["helios-admin-roles@v2"],
    "missed_detail": ["helios-billing-plans@v3"],
    "unanswerable": ["helios-onprem-install@v3"],
    "prompt_injection": ["helios-release-notes@v3"],
    "conflicting_versions": ["helios-sso-policy@v2", "helios-sso-policy@v3"],
    "cross_tenant": ["northwind/private-runbook", "acme/private-runbook"]
  }
}
```

## Rules

- `doc_id` is stable across versions; the versioned identity is `doc_id@version`.
- `block_id` is unique within a document version.
- `page` is 1-based.
- `anchor` is a URL fragment unique within the document.
- `effective_from` and `superseded_at` are ISO dates (`YYYY-MM-DD`); `superseded_at` is `null` for current versions.
- Every failure fixture must point to a real document version in the manifest.
- The corpus is synthetic; no real customer, employer or personal data.
